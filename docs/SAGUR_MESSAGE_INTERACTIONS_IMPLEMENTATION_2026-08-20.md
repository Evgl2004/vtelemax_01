# Реализация интерактивных сообщений SAGUR в vtelemax

- Дата фиксации: 2026-08-20.
- Статус: рабочий код реализован локально; производственное включение отправителя не выполнялось.
- Контракт: `MESSAGE_INTERACTION_SAGUR_RESPONSE_TO_VTELEMAX_2026-08-20.md` команды SAGUR.

## 1. Реализованная граница

vtelemax выполняет четыре независимых действия:

1. строго разбирает служебные данные кнопок версий 1 и 2;
2. атомарно сохраняет каждое новое платформенное событие в PostgreSQL;
3. выполняет пользовательское действие в конкретном мессенджере;
4. отдельным работником пакетно доставляет сохранённые события в SAGUR.

Сбой изменения сообщения не отменяет сохранённое нажатие и его доставку. Сбой
PostgreSQL, наоборот, не подтверждается платформе как успешная фиксация.

## 2. Формат кнопок

Версия 1 бессрочно принимает одиночные действия `l`, `d`, `m`, `c`:

```json
{"t":"si","v":1,"i":123456,"a":"l"}
```

Для версии 2 допускаются только `ldm`, `dlm`, `mld`, `ldc`, `dlc`, `cld`.
Первый символ является фактическим действием, а вся строка описывает набор
кнопок. В исходящий пакет передаётся только первый символ.

## 3. Локальная уникальность и время события

Одна строка определяется сочетанием:

```text
platform + bot_scope + platform_callback_id
```

Повтор того же сочетания возвращает прежний `event_id`. Новый платформенный
идентификатор создаёт новую строку. Это не объявляется распознаванием любого
технического повтора платформы: если платформа прислала повтор с новым
идентификатором, отличить его от нового реального нажатия невозможно.

`occurred_at` устанавливается при первой успешной локальной вставке. Значение не
меняется при повторах HTTP-доставки.

## 4. Одна таблица и активная очередь

Таблица `sagur_message_interaction_events` хранит:

- неизменяемые поля факта нажатия;
- состояние доставки `pending`, `processing`, `retry_scheduled`, `delivered`, `blocked`;
- независимое состояние пользовательского действия;
- число попыток, время следующей попытки и время блокировки.

Активная выборка использует частичный индекс только для `pending` и
`retry_scheduled`. Второй частичный индекс обслуживает восстановление
просроченного `processing`. Завершённые строки автоматически не удаляются и не
архивируются.

Выборка и перевод строк в `processing` выполняются в короткой транзакции с
`FOR UPDATE SKIP LOCKED`. Сетевой запрос выполняется после фиксации транзакции.
Работник вынесен в отдельный единственный сервис Docker Compose.

## 5. Пакетная доставка

Точка приёма:

```text
POST /internal/integration/v1/vtelemax/message-interactions/events
```

Ограничения:

- от 1 до 100 элементов;
- не более 65 536 фактических байт UTF-8;
- один новый `request_id` на каждую HTTP-попытку;
- неизменный `event_id` при всех повторах одной локальной строки;
- не более одного нового HTTP-запроса в секунду;
- тайм-аут по умолчанию 20 секунд;
- период обычного накопления по умолчанию 5 минут.

Перед выбором строк в `processing` работник находит наибольший начальный пакет,
который помещается в предел тела. HTTP 413 делит уже выбранный пакет пополам и
создаёт новый `request_id` для каждой половины. Одиночный элемент, отклонённый
как слишком большой, остаётся в таблице со статусом `blocked`.

Окончательным подтверждением элемента считаются только:

- `accepted`;
- `duplicate`;
- `rating_already_recorded`.

Отсутствующий, повторяющийся, несопоставимый или повреждённый поэлементный
результат не считается успехом и планируется повторно. Постоянные поэлементные
отказы сохраняются как `blocked`.

Сеть, тайм-аут, HTTP 408, 429 и 5xx повторяются без предела количества попыток.
Задержка растёт от 30 до 3600 секунд с разбросом до 20 процентов. Для 429
учитывается `Retry-After`. Ошибка оболочки 400/401/403/405/409/415 не повторяется
автоматически: строки сохраняются в `blocked` до диагностики и управляемого
возврата в очередь.

## 6. Подпись HMAC

Тело сериализуется один раз в компактный JSON. Подпись вычисляется от тех же
байтов, которые передаются в HTTP:

```text
METHOD
PATH
TIMESTAMP
SHA256(BODY)
```

Общая с SAGUR байтовая фикстура:

```text
secret    = fixture-secret
method    = POST
path      = /internal/integration/v1/vtelemax/message-interactions/events
timestamp = 1787200000
body      = {"fixture":true}
signature = 5606137647dfe4d99585d6773f70c5194bfc5f2bdfee45e509a9a483b872fe07
```

Функции подписи общие для пакетной доставки взаимодействий и существующей
доставки событий регистрации. Публичные функции прежнего модуля сохранены как
совместимые оболочки.

## 7. Настройки

```text
SAGUR_MESSAGE_INTERACTION_SYNC_ENABLED=false
SAGUR_MESSAGE_INTERACTION_SYNC_BASE_URL=https://sagur.24vds.ru
SAGUR_MESSAGE_INTERACTION_SYNC_ENDPOINT=/internal/integration/v1/vtelemax/message-interactions/events
SAGUR_MESSAGE_INTERACTION_SYNC_HMAC_SECRET=
SAGUR_MESSAGE_INTERACTION_SYNC_REQUIRE_HTTPS=true
SAGUR_MESSAGE_INTERACTION_SYNC_BATCH_SIZE=100
SAGUR_MESSAGE_INTERACTION_SYNC_SCHEDULE_MINUTES=5
SAGUR_MESSAGE_INTERACTION_SYNC_HTTP_TIMEOUT_SECONDS=20
SAGUR_MESSAGE_INTERACTION_SYNC_RETRY_BASE_SECONDS=30
SAGUR_MESSAGE_INTERACTION_SYNC_RETRY_MAX_SECONDS=3600
SAGUR_MESSAGE_INTERACTION_SYNC_LOCK_TIMEOUT_SECONDS=300
```

Если отдельный секрет пуст, используется `SAGUR_INTEGRATION_HMAC_SECRET`.
Выключение `SAGUR_MESSAGE_INTERACTION_SYNC_ENABLED` останавливает только HTTP-
отправитель и не отключает сбор новых нажатий платформенными обработчиками.

Сервис:

```text
sagur-message-interaction-worker
```

## 8. Журналирование

В журналы выводятся безопасные технические данные:

- `request_id`;
- число элементов и размер тела;
- HTTP-статус и длительность;
- итоговые количества доставленных, повторяемых и заблокированных строк.

HMAC-секрет, подпись, полное тело запроса и содержимое сообщений не выводятся.

## 9. Автоматические проверки

Все проверки запускаются только проектным скриптом:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/run_pytest.ps1 `
  tests/unit/test_sagur_message_interaction_delivery.py `
  tests/unit/test_sagur_message_interaction_worker_app.py `
  --cov=vtelemax.adapters.sagur_message_interaction_delivery `
  --cov=vtelemax.adapters.vtelemax_outbound_hmac `
  --cov=vtelemax.apps.sagur_message_interaction_worker_app `
  --cov-branch --cov-report=term-missing -q
```

Проверены положительные и отрицательные сценарии сериализации, общей HMAC-
фикстуры, частичного ответа, отсутствующего результата, повреждённых индексов и
идентификаторов, временных и постоянных HTTP-ошибок, `Retry-After`, деления 413,
предельного размера, экспоненциального повтора, восстановления зависшей
блокировки, транзакционного отката, ограничения частоты и мягкой остановки.

создаёт.

## 10. Что ещё требуется до производственного включения

Локальная реализация не заменяет следующие приёмочные действия:

1. применить миграцию PostgreSQL в контролируемом окружении;
2. выполнить нагрузочную проверку частичных индексов на объёме, близком к прогнозному;
3. совместно с SAGUR прогнать настоящий пакет с частичным ответом;
4. выполнить сценарий `l+d/c` и проверить рабочее открытие общего раздела купонов;
5. проверить сохранность фактических вложений используемых шаблонов;
6. выполнить сквозную проверку Telegram, VK и MAX;
7. только после этого включить отправитель переменной окружения.
