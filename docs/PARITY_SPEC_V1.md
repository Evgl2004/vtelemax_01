# Parity Spec v1 (UI/UX и данные)

Документ фиксирует соответствие монорепозитория `vtelemax` исходным прототипам Telegram/VK/MAX и целевым доработкам проекта.

Дата фиксации: `30.03.2026`.

## 1. Источники сравнения

Прототипы:

1. Telegram: [Evgl2004/aiogram_bot_01](https://github.com/Evgl2004/aiogram_bot_01)
2. VK: [Evgl2004/vkbottle_01](https://github.com/Evgl2004/vkbottle_01)
3. MAX: [Evgl2004/maxbot_01](https://github.com/Evgl2004/maxbot_01)

Текущий проект:

1. Core onboarding/контент: `src/vtelemax/core/*`
2. Адаптеры: `src/vtelemax/adapters/telegram/*`, `src/vtelemax/adapters/vk/*`, `src/vtelemax/adapters/max/*`
3. SQL-схема: `migrations/sql/*`

## 2. Легенда статусов

1. `OK` — реализовано и соответствует целевому поведению.
2. `PARTIAL` — работает, но есть ограничение или упрощение.
3. `MISMATCH` — еще не доведено до целевого поведения.

## 3. Матрица паритета v1

| № | Сценарий | Целевое поведение | Статус | Примечание |
|---|---|---|---|---|
| 1 | `/start` для нового пользователя | Единый onboarding во всех адаптерах | `OK` | Запуск общей логики onboarding через core |
| 2 | Экран правил | Текст + кнопка-ссылка на документы + inline-кнопка `✅ Согласен` | `OK` | Реализовано в Telegram/VK/MAX |
| 3 | Переход после согласия с правилами | После `✅ Согласен` открывается шаг телефона | `OK` | Единый переход по FSM |
| 4 | Получение телефона | Telegram/MAX: контакт-кнопка, VK: текстовый ввод | `OK` | Поведение соответствует платформенным ограничениям и прототипам |
| 5 | Сокращенная регистрация | Шаги: правила -> телефон -> имя -> согласие на рассылку -> меню | `OK` | Принято как целевой v1-сценарий |
| 6 | Кнопка `Профиль` | Показ карточки профиля в формате финального экрана регистрации | `OK` | Вывод унифицирован для всех 3 платформ |

| 8 | SQL-схема поддержки и модерации | Таблицы тикетов/сообщений и кросс-мессенджерная доставка pending | `OK` | Есть `support_tickets`, `support_messages`, статус доставки |
| 9 | Полный legacy-опрос после телефона | Полная анкета как в исходных прототипах (фамилия/пол/дата/email/подтверждение) | `MISMATCH` | В v1 сознательно оставлена сокращенная регистрация |
| 10 | Повторы доставки ответов модератора | Автоматические retry при `failed` | `MISMATCH` | Зафиксировано как точка развития |

## 4. Зафиксированные решения v1

1. Проект работает в режиме строгой идентификации пользователя по единой персоне и единому номеру телефона без дублей.
2. Регистрация в v1 укороченная по UX, но модель данных хранится полной, чтобы без миграционного долга перейти к полному сценарию.
3. Меню и тексты выносятся в общий core-контракт, а различия допускаются только там, где это диктует API платформы.

## 5. Открытые точки развития

1. Вернуть полный legacy-сценарий анкеты из прототипов как отдельный режим или этап после укороченной регистрации.
2. Добавить retry-политику для доставки сообщений модератора (`failed -> retry`).
3. Расширить e2e/smoke-чеклист по всем трем адаптерам на сервере для каждого релиза.

## 6. Definition of Done для паритета

Сценарий считается завершенным, когда одновременно выполнены условия:

1. В таблице выше статус сценария `OK`.
2. Тесты `pytest` в репозитории зеленые.
3. Серверный smoke пройден в Telegram, VK и MAX.
4. Изменение зафиксировано отдельным логическим коммитом с описанием на русском языке.
