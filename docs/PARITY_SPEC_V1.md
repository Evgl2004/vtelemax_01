# Parity Spec v1 (UI/UX)

Документ фиксирует соответствие текущего монорепозитория `vtelemax` прототипам Telegram/VK/MAX по пользовательскому интерфейсу и onboarding-сценариям.

Цель:

1. Снять «расхождения ожиданий» между прототипами и текущей реализацией.
2. Зафиксировать целевое поведение для следующего этапа доработки.
3. Дать понятный чек-лист для самостоятельной доработки без потери паритета.

Дата фиксации: `26.03.2026`.

## 2. Легенда статусов

1. `OK` — соответствует прототипам или согласованному целевому поведению.
2. `PARTIAL` — частично соответствует (есть платформенные отклонения).
3. `MISMATCH` — поведение отличается и требует доработки.

## 4. Платформенные ограничения (важно)

1. Telegram не поддерживает `request_contact` в inline-кнопке, только в `ReplyKeyboard`.
2. VK в текущем прототипе регистрации использует ручной ввод телефона текстом.
3. MAX поддерживает контакт-вложение через `RequestContactButton`; это надо использовать для паритета.

Эти ограничения считаются допустимыми различиями транспорта, но не должны приводить к визуально-логическим рассинхронам сценария.

## 5. Приоритеты доработки

`P0`:

1. Вернуть кнопку-ссылку на документы в шаге правил.
2. Вернуть MAX-сценарий получения телефона через `RequestContactButton` и обработку contact attachment.
3. Принять продуктовое решение по Telegram main/support меню: inline (как в прототипе) или ReplyKeyboard.

`P1`:

1. Убрать дублирование текста шага правил в core.
2. Сделать платформенные тексты шага телефона.
3. Зафиксировать состав главного меню (строгий паритет или расширенный режим).

`P2`:

1. Добавить расширенные parity-тесты UI-поведения.
2. Добавить smoke-чеклист перед каждым релизом по Telegram/VK/MAX.

`P3` (новый приоритет):

1. Реализовать полный сценарий регистрации (FMS) — сбор профиля, подтверждение анкеты, согласие на уведомления, интеграция с iiko.

## 6. Чек-лист самостоятельной доработки

Этот шаблон нужен, чтобы новые изменения можно было вносить без регресса между платформами.

1. Зафиксировать сценарий в `docs/PARITY_SPEC_V1.md` (новая строка матрицы).
2. Обновить core-контент/контракт (`guest_content.py`, `menu_contract.py`, `onboarding.py` при необходимости).
3. Обновить платформенные адаптеры и рендеры:
   1. `adapters/telegram/*`
   2. `adapters/vk/*`
   3. `adapters/max/*`
4. Добавить тесты:
   1. unit по каждому затронутому адаптеру;
   2. adapter-contract тест на межплатформенный паритет;
   3. «грязные» кейсы (невалидные payload, пустой ввод, некорректное состояние).
5. Запустить `pytest` целиком.
6. Выполнить smoke-проверку на сервере:
   1. `/start`;
   2. шаг правил;
   3. шаг телефона;
   4. переход в меню.
7. Обновить статус строки в `Parity Spec` (`OK/PARTIAL/MISMATCH`).

## 7. Definition Of Done для UI-паритета

Фича считается завершенной только если:

1. В матрице `Parity Spec` по сценарию статус `OK`.
2. Тесты `pytest` зелёные.
3. Smoke на сервере по всем 3 мессенджерам подтверждён.
4. Изменение зафиксировано отдельным логическим коммитом.
