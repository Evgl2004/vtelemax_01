# QR-сценарий виртуальной карты (Telegram/VK/MAX)

Документ фиксирует текущее поведение раздела `🪪 Виртуальная карта` в монорепозитории `vtelemax`.

## 1. Единый доменный контракт

В `core` use-case `GetVirtualCardUseCase` возвращает:

1. `status` и `message` для итогового текстового ответа.
2. `parse_mode` для платформы.
3. `card_numbers: tuple[str, ...]` — список номеров карт для генерации QR.

Это позволяет не парсить номера карт из текста в адаптерах и роутерах.

## 2. Поведение по платформам

1. Telegram:
   Отправляются `photo`-сообщения с QR и подписью `💳 Карта: <номер>`, затем итоговый текст раздела.
2. VK:
   QR генерируется в PNG, загружается через `photos.getMessagesUploadServer` + `photos.saveMessagesPhoto`, затем отправляется сообщение с `attachment`.
3. MAX:
   QR загружается через `get_upload_url(UploadType.IMAGE)` и отправляется как attachment изображения.

## 3. Общая инфраструктура QR

Вынесен модуль `src/vtelemax/infrastructure/qr.py`:

1. `generate_qr_png_bytes(data: str) -> bytes`
2. `QrGenerationError`

Модуль используется всеми роутерами и гарантирует единый формат QR-картинки.

## 4. Fallback и отказоустойчивость

1. Если QR не удалось сгенерировать или загрузить, пользователь все равно получает итоговый текст раздела и номер карты.
2. Ошибки QR-ветки логируются и не блокируют основной пользовательский сценарий.

## 5. Зависимости

Для генерации QR добавлена зависимость:

1. `qrcode[pil]>=8.2,<9.0`

Установка выполняется стандартным способом через `pip install -e .[dev]` (или ваш текущий способ установки зависимостей проекта).
