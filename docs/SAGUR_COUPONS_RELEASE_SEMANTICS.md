# Семантика release для купонов SAGUR

Дата фиксации: 2026-05-15.

Документ фиксирует обновленный контракт SAGUR ↔ vtelemax для отмены рассылочных
кампаний и повторного использования купонов.

## Короткое подтверждение

vtelemax поддерживает семантику:

```text
status_update + status=canceled = release купона
```

Это означает:

- купон исчезает из пользовательского меню `🎟️ Купоны`;
- привязка `купон ↔ гость` удаляется из таблицы пользовательских купонов;
- тот же `coupon_series + coupon_code` может быть назначен другому гостю будущим
  событием `assignments`;
- повторная обработка того же `event_id` идемпотентна;
- повторный `canceled` по уже освобожденному купону с новым `event_id` тоже
  возвращает штатный `ok=true` и не создает скрытую "мертвую" привязку.

Дополнительный флаг вроде `release_to_pool=true` на текущем этапе не нужен.

## Достаточность payload

Для release в vtelemax достаточно текущей структуры:

- `campaign_id`;
- `assignment_id`;
- `person_id`;
- `phone_e164`;
- `coupon_series`;
- `coupon_code`;
- `status=canceled`;
- `status_at`;
- `meta.cancel_reason`.

Фактический поиск активной привязки выполняется по:

```text
person_id + coupon_series + coupon_code
```

`assignment_id`, `status_at` и `meta.cancel_reason` принимаются в составе raw
payload и сохраняются в аудите события `sagur_coupon_events.payload_json`.

Если в будущем появится сценарий, где один и тот же `person_id` может иметь
несколько конкурентных назначений с одинаковыми `coupon_series + coupon_code`, для
строгого различения потребуется добавить `assignment_id` в модель
`person_coupons`. В текущем контракте такой сценарий не предполагается.

## Поведение статусов

`canceled`:

- используется для release только при `direction=status_update`;
- удаляет найденную строку из `person_coupons`;
- не создает новую строку, если привязка уже была снята;
- не попадает в пользовательский UI.

`used`:

- означает, что купон применен;
- убирается из активного UI;
- не освобождается vtelemax для повторного назначения.

`used_after_campaign`:

- означает поздний факт применения купона после завершения кампании;
- убирается из активного UI;
- хранится отдельным статусом для аудита и отчетности;
- не освобождается vtelemax для повторного назначения.

`expired`:

- означает, что срок действия истек;
- убирается из активного UI;
- не освобождается vtelemax для повторного назначения.

`reserved` и `sent`:

- считаются активными для пользовательского UI;
- отображаются в разделе `🎟️ Купоны`, если `is_visible=true`.

## Идемпотентность

Идемпотентность работает на двух уровнях:

- повтор того же `event_id` возвращает `ok=true` и не применяет изменения второй
  раз;
- повторный `canceled` с новым `event_id`, когда привязки уже нет, сохраняет
  событие аудита и возвращает успешный результат без создания записи в
  `person_coupons`.

## Критерии приемки

Покрытые сценарии:

- `assignments` создает видимый купон у первого гостя;
- `status_update: canceled` удаляет привязку и купон исчезает из UI первого
  гостя;
- повтор того же `event_id` не меняет состояние и не дает ошибку;
- повторный `canceled` после release не создает скрытую запись;
- будущий `assignments` того же купона другому гостю создает новую видимую
  привязку.
