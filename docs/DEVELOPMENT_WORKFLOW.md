# Процесс разработки

## 1. Стратегия веток

1. `main` — базовая стабильная ветка.
2. `codex/develop-cai` — основная рабочая ветка разработки.

## 2. Принцип работы

1. Работа ведется пошагово.
2. После логически завершенного шага делается коммит.
3. Сообщения коммитов пишутся на русском языке.

## 3. Правила коммитов

Рекомендуемый формат:

1. Короткий заголовок в повелительном наклонении.
2. Конкретика: что добавлено/изменено и зачем.

Примеры:

1. `Инициализировать монорепозиторий vtelemax и тестовый каркас`
2. `Добавить доменный сервис строгой идентификации по телефону`

## 4. Порядок этапов

1. Анализ и фиксация архитектуры.
2. Обсуждение подхода и подтверждение решений.
3. Фиксация пошагового плана в `docs/DEVELOPMENT_PLAN.md`.
4. Реализация малыми итерациями по зафиксированному плану.
5. Тестирование каждого шага.
6. Документирование изменений.
