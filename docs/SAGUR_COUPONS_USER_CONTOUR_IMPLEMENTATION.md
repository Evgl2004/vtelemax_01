# Пользовательский контур купонов SAGUR

Документ фиксирует результат этапа, на котором backend-прием событий купонов от
SAGUR был доведен до пользовательского сценария в ботах Telegram, VK и MAX.

Дата фиксации: 2026-05-15.

## Цель этапа

Сделать production-ready UI/UX для купонов пользователя во всех поддерживаемых
мессенджерах, не ломая уже реализованный backend-контур:

- прием событий SAGUR через `POST /internal/integration/v1/sagur/coupons/events`;
- HMAC-проверку входящих событий;
- идемпотентность по `event_id`;
- обработку направлений `assignments` и `status_update`;
- хранение и чтение купонов через `SQLAlchemySagurCouponsRepository`.

## Ключевая пользовательская логика

Купоны доступны из профиля через кнопку `🎟️ Купоны`.

При открытии раздела:

- кнопка `Общие` показывается только при наличии видимых глобальных купонов с
  `venue_code = "__global__"`;
- показываются только те заведения, где есть хотя бы один видимый активный
  купон;
- если купонов нет, пользователь получает понятный пустой экран и кнопку
  возврата назад.

В списке купонов элементы называются по последним четырем символам
`coupon_code`, чтобы не раскрывать длинный код прямо в меню и сохранить
узнаваемость купона.

При открытии конкретного купона бот отправляет:

- QR-код по полному `coupon_code`;
- текстовую карточку с `promo_text`, заведением, кодом, статусом и техническими
  атрибутами, полезными для диагностики.

Неактивные статусы не попадают в пользовательские списки:

- `used`;
- `expired`;
- `canceled`;
- `error`.

Активными для UI считаются:

- `reserved`;
- `sent`.

## Общий core-слой

Добавлен модуль `src/vtelemax/core/coupon_content.py`.

Он содержит платформенно-независимое построение экранов:

- `build_coupons_root_view` - корневой экран раздела купонов;
- `build_coupons_list_view` - список купонов внутри области или заведения;
- `build_coupon_card_view` - карточка конкретного купона и payload для QR;
- `is_coupon_visible_for_guest` - единая проверка видимости купона;
- `coupon_tail4` - безопасное получение последних четырех символов кода.

Такой слой нужен, чтобы Telegram, VK и MAX не расходились в бизнес-правилах.
Адаптеры отвечают только за транспорт, callback/payload и клавиатуры.

## Чтение из базы

`SQLAlchemySagurCouponsRepository` теперь дополнительно фильтрует пользовательские
выборки по активным статусам.

Фильтр применяется в методах:

- `count_visible_global_coupons`;
- `list_visible_venues`;
- `list_visible_coupons`.

Это защищает UI от старых или промежуточных данных, где `is_visible = true`, но
статус уже стал `used`, `expired`, `canceled` или `error`.

## Telegram

Реализована полная навигация купонов в Telegram.

Основные изменения:

- `TelegramIdentityAdapter` получает `coupon_session_factory`;
- callbacks `coupon_scope:*` и `coupon_show:*` обрабатываются внутри адаптера;
- для длинных идентификаторов заведений используется безопасное кодирование
  token в `callback_data`;
- если callback Telegram приближается к лимиту длины, используется короткий
  per-user token;
- экран QR ведет себя как экран карты: QR отправляется отдельным сообщением и не
  перегружается меню-клавиатурой;
- добавлена отдельная клавиатура карточки купона с возвратом в раздел купонов;
- исправлена кнопка возврата из списка купонов: она ведет именно назад к
  разделу купонов, а не выглядит как отмена редактирования профиля.

Маршрутизатор Telegram:

- распознает callback-префиксы купонов;
- отправляет QR через общий генератор `generate_qr_png_bytes`;
- удаляет или очищает старую callback-клавиатуру при открытии карточки, чтобы
  меню не мешало QR-экрану.

## VK

Реализована паритетная логика для VK.

Основные изменения:

- `VkIdentityAdapter` получает `coupon_session_factory`;
- payload-команды `coupon_scope:*` и `coupon_show:*` обрабатываются отдельно от
  обычных `GuestMenuAction`;
- `VkGuestMenuAdapter` умеет строить корневой экран купонов, список купонов и
  карточку купона;
- QR отправляется отдельным сообщением перед текстовой карточкой;
- для callback events старое сообщение удаляется перед отправкой QR и новой
  карточки, чтобы интерфейс не оставлял лишних кнопок.

## MAX

Реализована паритетная логика для MAX.

Основные изменения:

- `MaxIdentityAdapter` получает `coupon_session_factory`;
- строковые payload `coupon_scope:*` и `coupon_show:*` поддержаны в общем
  обработчике входящих сообщений;
- `MaxGuestMenuAdapter` строит корневой экран, список и карточку купона;
- QR отправляется отдельным сообщением через штатный upload-flow MAX;
- при callback-навигации старое меню удаляется перед отправкой карточки купона.

## Подключение приложений

`session_factory` передается в coupon-aware адаптеры в приложениях:

- `src/vtelemax/apps/telegram_app.py`;
- `src/vtelemax/apps/vk_app.py`;
- `src/vtelemax/apps/max_app.py`.

Это делает чтение купонов из PostgreSQL частью штатного runtime-контура каждого
бота.

## Диагностика и отказоустойчивость

В адаптерах добавлены понятные fallback-экраны:

- если БД или репозиторий временно недоступны;
- если callback содержит некорректный `coupon_id`;
- если купон уже не найден, скрыт или перешел в неактивный статус;
- если короткий callback-token устарел и больше не может быть восстановлен.

Логи в критичных местах сформулированы с русским и английским смыслом, чтобы их
было удобно читать и человеку, и ИИ-ассистенту при диагностике.

дублировать бизнес-правила в отдельных адаптерах.
